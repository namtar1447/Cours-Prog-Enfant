Thonny — L'atelier du programmeur

🎮 Analogie

Imagine que tu veux construire un niveau dans un jeu vidéo. Tu as besoin d'un endroit pour dessiner la carte, d'une fenêtre pour voir le résultat, et d'un panneau qui te dit ce qui existe dans le niveau.

Thonny, c'est pareil — mais pour écrire du Python.

En programmation, on appelle ça un IDE — un outil qui regroupe tout ce dont tu as besoin au même endroit :

✏️
Écrire
Un éditeur de texte intelligent
▶️
Exécuter
Un bouton pour lancer le programme
🔍
Inspecter
Voir ce qui se passe à l'intérieur
Thonny est gratuit, en français, et il est conçu spécialement pour apprendre à programmer. C'est l'outil parfait pour commencer.

La barre d'outils et les onglets

Les boutons que tu utiliseras à chaque programme

BoutonRaccourciÀ quoi ça sert
▶ Run F5 Lance ton programme
⏹ Stop Ctrl+F2 Arrête le programme s'il est bloqué
💾 Save Ctrl+S Sauvegarde le fichier

L'étoile ★ — ton meilleur indicateur

Quand l'onglet affiche une étoile ★, le fichier n'est pas encore sauvegardé. Si tu cliques sur ▶ sans sauvegarder, Thonny sauvegarde automatiquement — mais prends l'habitude de faire Ctrl+S toi-même avant de lancer.

★ <sans nom> ← pas sauvegardé
exercice_01.py ← sauvegardé ✓

Les erreurs — pas de panique !

🎮 Analogie

Quand tu rates un niveau dans un jeu, le jeu te dit où tu as échoué et pourquoi. Un message d'erreur Python, c'est pareil — c'est de l'aide, pas une punition.

Tous les programmeurs font des erreurs. Ce qui distingue un bon programmeur, c'est de savoir lire les messages d'erreur.

Comment lire un message d'erreur

Un message d'erreur Python (un traceback) dit toujours trois choses :

📍
Où
Le numéro de ligne
🏷️
Quel type
NameError, SyntaxError…
💬
Quoi
Le message explicatif

Exemple 1 — Faute de frappe dans le nom

Code : prnt("Papa")

>>> %Run -c $EDITOR_CONTENT Traceback (most recent call last): File "<string>", line 1, NameError: name 'prnt' is not defined
📍 line 1 → l'erreur est à la ligne 1

🏷️ NameError → Python ne connaît pas ce nom

💬 'prnt' is not defined → tu as écrit prnt au lieu de print

Exemple 2 — Guillemet oublié

Code : print("Papa)

>>> %Run -c $EDITOR_CONTENT Traceback (most recent call last): File "<string>", line 1 print("Papa) ^ SyntaxError: unterminated string literal
📍 line 1 → l'erreur est à la ligne 1

🏷️ SyntaxError → le code est mal écrit (comme une faute de grammaire)

💬 unterminated string → une chaîne de texte n'est pas fermée — il manque un "
✅ La règle d'or face à une erreur :
  1. Lis la dernière ligne du message — c'est là que l'explication est
  2. Regarde le numéro de ligne indiqué
  3. Cherche une faute de frappe ou un guillemet / parenthèse manquant
